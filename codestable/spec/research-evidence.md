# 研究证据流程

`src/smart_search/jev_search.py` 负责 Jev 选路、渠道执行和研究结果组装；`src/smart_search/jev.py` 负责有类型的概率判断；`src/smart_search/evidence.py` 提供共用的正文摘录。普通 search 保持单轮检索，不自动启动研究或总结。

## 从发现到正文

- research 先发现候选来源，再读取原文并评估缺口。需要正文时，达到既有路由阈值的 fetch 至少获得一个渠道名额，其余名额仍按 Jev 分数选择；没有合格读取动作时允许继续发现来源。
- 候选 URL 先按指定来源、问题相关词和主机分散排序，再限制为最多 20 个；该上限控制候选判断规模，不扩大每轮执行名额。已读 URL 不重复调度，新的来源可以在后续轮次进入候选池。
- 每个读取候选包含发现阶段的标题、摘要和提供方，供 Jev 判断其是否值得读；成功后的引用保留发现标题。选路的 state 与 questions 按序列化后最多 32,000 字符分批，全部动作的局部分数还原到全局身份后统一排序；单个判断仍不能容纳时显式报错。分批会增加 Jev 调用次数，仍受共享截止时间约束。
- 请求明确表示“只读取”“只基于”“仅使用”指定 URL 或相应英文限制时，只调度这些 URL 的读取，不从其他网页替代证据。“优先”不等同于“仅限”。这是一组明确措辞的解析规则，不是任意自然语言限制的完整理解器。
- 正文读取和主搜索模型保留本轮 retrieval timeout，不因快速索引结果到达而取消。外部取消和共享截止时间仍生效，评估与总结使用剩余预算。
- research 与直接 fetch 复用 `src/smart_search/service.py` 中的抓取回退链。回退只能使用已配置、已启用、未被禁用且被调用方允许的提供方；fallback=off 保持单提供方。每次空结果、错误和成功均保留在 provider_attempts，正文注明实际成功提供方。
- 已读取的非空正文若被评估为无用，后续轮次可以在同一 URL 尝试尚未调用的读取提供方；原始抓取版本仍保留，不把一次无用摘录当作原文不存在或全部无关的证明。

## 文档与摘录

Context7 分开传递技术名称和完整问题。Jev 可以在普通搜索和研究中评估库是否相关；明确判为不相关时不读取第一项。缺少 Jev 或判断不可用时，只允许唯一名称匹配，否则返回可诊断错误并走原有渠道回退。

正文摘录使用英文词及中文双字词匹配，规范化 Unicode 连字符，并优先摘要、实验、结果和结论段落，降低密集链接、参考文献段落的权重；评估同时按相关性选择来源，遗漏和截断仍显式标记。研究的无模型报告复用相同摘录方法，auto 判断同时看到将交付的证据报告，不能仅凭隐藏正文中存在事实就认为已交付答案。该摘录是有限词法启发式，不保证找到所有关键事实，也不替代 Jev 的充分性判断。

同 URL 的不同抓取版本保留正文及提供方，不按多个独立来源互证。评估带 source_identity 和 unique_read_sources，引用与 sources 按 URL 去重。

## 完成与失败

研究结果保留原有 ok 的检索成功含义，另提供 completion：retrieval、evidence、synthesis、answer 和 unique_read_sources。answer=complete 需要存在已读证据、缺口关闭且计划中的总结未失败；它反映本次工作流判断，不是外部人工验证结论。

总结失败时保留证据报告及原始错误，degraded=true、partial_success=true、completion.answer=partial；不把已齐的证据缺口伪装成未齐，也不把检索成功等同于总结成功。调用方需要完整答案时应检查 completion.answer。

## 限流

OpenAI 兼容适配器与提供方健康记录共用 retry hint 解析：支持 Retry-After、retry-after-ms 和错误正文的 try again in 提示。已知短暂限流按上游给出的等待时间冷却，既有重试次数和共享截止时间仍约束重试。没有有效提示时使用原有策略，鉴权失败策略保持不变。

本流程不增加密钥或设置项；已有的 Jev、抓取提供方及独立总结模型配置继续生效。
