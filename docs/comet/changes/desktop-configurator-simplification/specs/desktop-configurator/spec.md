# Smart Search 配置器

## 产品边界

App 用于配置、显式测试以及帮助安装/更新电脑上的 CLI 和 Agent Skills。外部 CLI 是终端和 Agent 的正常调用入口，关闭、更新或卸载 App 不影响该安装。App 私有辅助进程仅供配置、测试和安装管理，不发布为 CLI，不加入 PATH，不建立指向 App 的用户命令链接。公开 npm/Python CLI 的功能和输出保持兼容。

### Scenario: App 和用户 CLI 独立

WHEN 使用 App 配置、安装 CLI 和生成 Skills，THEN 外部调用指向已核实的 App 目录外安装；App 不再有启用/复制内置 CLI 的入口，私有程序不能回退执行公开 CLI 搜索命令；App 路径不可用时外部 CLI 仍能运行。没有外部 CLI 时仍可打开配置并显式测试服务商。

## 界面范围

两端均为“配置”“测试”“CLI 与 Skills”“设置”四个目的明确的页面，默认进入配置。配置保留服务商、Key、必要路由及保存/放弃/测试；测试保留输入、开始/取消、可读结果与必要错误。移除独立概览和活动工作台，运行反馈就地呈现。高级排错材料按需查看，不变成新的常驻控制台或按钮矩阵。

### Scenario: 日常界面只保留配置器的操作

WHEN 用户依次访问四个页面，THEN 每个页面有明确目的和当前主要操作，找不到旧概览、常驻活动、内置 CLI、运行环境管理、开发后端路径/超时等入口；必要配置、测试结果、错误和取消仍可访问。切页和状态刷新不丢草稿、选择或运行进度。

## Skills 选择与单一操作

勾选框表示本次要安装/更新的 Agent，不表示 Agent 已安装、Skill 已加载或开关即可卸载。行内显示简洁安装状态，路径及差异按需查看。至少选择一个有效目标且没有冲突操作时，“安装/更新所选 Skills”立即可用，不要求用户先点检查，也不按 needs_update 排除已选目标。零选择时有清楚提示。

### Scenario: 选择立即决定主按钮状态

WHEN 在首次启动、仅有旧缓存或目标未安装/已有相同内容的状态下选择 OpenCode 或其他目标，THEN 选择数和主按钮立即更新；无需刷新页面。取消最后一项后停止提交并提示选择目标；取消勾选不删除任何文件。Windows/macOS 一致。

点击主操作后，App 内部取得并校验官方 stable 来源、重新核对所选目标、建立必要备份并同步；阶段连续显示为一个操作。来源检查失败显示可重试原因，不修改已安装文件。完成后刷新状态并保持选择；相同内容明确显示已是最新且不重复写入/备份。后台检查和页面刷新不能把用户选择改回默认值。

### Scenario: 一次操作完成可信检查与安装更新

WHEN 选定目标并点击安装/更新，THEN 无需另外执行检查最新 Skills、刷新本机状态或准备运行环境即可得到完成/无变化/失败结果；请求仅处理点击时选定的目标，失败可从同一操作重试。未选目标、额外文件和其他 Skills 保留，来源及目标过期变化被重新核对。

## CLI 安装与维护

“CLI 与 Skills”页仅有一个 CLI 状态区和随状态变化的动作：未安装时安装，已安装且有新版时更新，失败或运行时缺损时重试/修复。检测、健康组件复用、下载校验、必要依赖安装和实际版本验证在操作内完成。普通用户不必操作 Node/Python/npm 检测面板。既有安装仍使用原管理器；未知/冲突/无权限的来源解释具体原因，不另建副本冒充修复。

### Scenario: CLI 准备不需要手动检测步骤

WHEN CLI 缺失、正常、过旧、运行时损坏或来源冲突，THEN 页面显示准确状态和一个适用动作；点击安装/更新后按已验证计划完成并读回版本。健康组件不重装，App 与用户原 PATH/管理器/其他程序保持独立；下载失败或安装失败不显示成功。

## App 更新与设置

设置只保留语言、外观、配置目录、App 版本与更新、必要关于信息。App 更新使用现有 Velopack/Sparkle，一个主操作按状态显示检查更新、更新、重试或进度；移除常驻迁移说明、手动刷新已安装版本、复制内置调用及下载后再另找安装按钮的自定义流程。仅在真实无法应用更新时给出一次可执行指引。底层签名、完整性、差分/完整回退与安全重启仍保留。

### Scenario: 更新流程简单且状态真实

WHEN 检查或执行 App 更新，THEN 用户只需使用当前主操作，能区分检查中、可更新、进行中、成功/失败；下载完成不冒充安装完成。设置里没有常驻旧版迁移与内置引擎控制。App 更新不升级或替换外部 CLI；必要异常只在发生时说明。

## 数据与并发保护

精简只改变面向用户的路径，不能去掉源/目标校验、Key 脱敏、配置乐观锁、不同内容备份与原子写入。环境安装、CLI 更新、Skills 写入、配置目录切换和 App 更新保持合理互斥；未保存草稿和当前任务不能被更新重启丢失。只取消可取消阶段，不强杀包管理器或外部 CLI。

### Scenario: 精简不破坏用户文件和进行中的工作

WHEN 有草稿、并发写入、目标变化、不安全路径、无权限、离线或取消请求，THEN 必要保护仍生效，状态和错误就地可见，操作可安全重试；原配置/Key、未选 Skills 和外部 CLI 不被静默覆盖、迁移、卸载或强杀。

## 双语和原生一致性

复用 WinUI/SwiftUI 原生组件及现有视觉系统，中文与英文操作含义一致。使用普通产品词语；内部 backend、runtime、migration、检查层级等不占据主流程。控件可用键盘操作，有可见焦点与文字状态；在当前最小窗口中主要按钮可访问，不增加嵌套滚动和弹窗链。

### Scenario: 两端界面一致且可操作

WHEN 切换平台、语言、主题或缩小至支持的窗口尺寸，THEN 四页目的、选择语义、主操作和反馈一致，长文案能换行，草稿与选择不被重置；必要说明不依赖颜色或鼠标悬停才可理解。

## 文档与验证

产品定位、协议、用户指南和测试应描述配置器及独立 CLI，失效的按钮/方法/资源不得继续引导用户走旧流程。保留 CLI 及签名/更新的既有能力和历史证据。测试使用隔离配置、安装和 Skills 目录；真实外部 API、GUI、正式发布和个人安装分别记录，不由静态检查代替。

### Scenario: 交付可验证且原功能保持

WHEN 完成候选，THEN Skills 选择/首次检查/失败重试/无变化回归、App/CLI 解耦、适用 Python/native 测试与构建有当前版本证据；文档无旧流程矛盾。独立 Verifier 逐项核验，用户得到精简 GUI 操作清单；未经授权不替换正式安装或发布稳定版。
