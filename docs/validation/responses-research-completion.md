# Responses 联网与 research 交付验证

验证日期：2026-11-02。环境为 Windows、Python 3.12.12、源码 CLI 0.1.34，基础提交为 69f48fc。配置保持主搜索 `gpt-6.1-sol`、Responses、`web_search`，Jev 路由与 auto + Sol 专用总结。本轮不更改用户配置，不替换官方安装版。

## 修复契约

- 启用 Responses 联网工具的 search 请求发送 `tool_choice=required`；至少一个 `web_search_call` 完成才接受结果，流式与非流式均适用。带引用不能替代实际工具执行。总结不带搜索工具。
- 摘录先保留文章自身题名、年份和 DOI，序列化预算收紧时重新摘录。既有总字符上限不变。
- 已读页面的相关同源 Markdown 链接进入未读详情候选；限定 URL 范围继续约束调度，安装包、图片、签名和清单链接不进入正文读取候选。后续主模型接收独立的证据上下文；索引服务不接收长正文充当查询。
- 配置了可用总结模型时，true 或有 Jev 的 auto 在总时限内预留 40%、最多 60 秒给最终评估与总结。最终评估不受提前的发现截止时间阻断；实际总结的超时和取消分别记录。
- 相同已读证据在同次研究内复用判断，全局分数不能抹掉单项实质缺口；门槛不降低。选路历史只传有界操作摘要，完整工具轨迹留在诊断结果中。
- 同步公开和打包技能的 Context7 匹配说明及 OpenAI Responses 配置提示。

行为规格见 [研究证据流程](../../codestable/spec/research-evidence.md)。协议依据为实际获取的 [OpenAI web search 指南](https://developers.openai.com/api/docs/guides/tools-web-search?api-mode=responses)：auto 允许不搜索，required 可要求调用工具，返回包含 web_search_call 的状态。

## 自动回归

新增 24 项检查，覆盖 HTTP 边界上的工具缺失、失败、未完成和完成，流式 output_item.done、非流式、总结工具隔离、长文元数据、详情链接及限定范围、后续主模型上下文、全局与单项评分矛盾、慢读取下的总结预算、最终评估越过发现截止时间、相同证据复用、总结超时与取消，以及完整工具轨迹或超长标题导致的下一轮选路超限。

相关回归：285 项通过。全量回归在空 LOCALAPPDATA 下执行，避免默认值测试读取个人配置：

```powershell
$env:PYTHONUTF8 = '1'
$validationProfile = Join-Path (Get-Location) ('_tmp/pytest-' + [guid]::NewGuid().ToString('N'))
$env:LOCALAPPDATA = $validationProfile
python -m pytest -q
```

结果：**1309 passed，19 skipped**。跳过项沿用平台等条件。9 份公开与打包技能文件一致，mock smoke 通过；工作区结构与规格检查通过。本轮没有新增运行依赖或配置字段。

## 受控 CLI 验证

使用 localhost HTTP 提供方、虚构密钥和独立配置启动真实 CLI：

| 返回条件 | 结果 |
|---|---|
| 有正文与引用，但无 web_search_call | quality_error，退出码 4 |
| 搜索工具 failed，但仍带正文与引用 | quality_error，退出码 4 |
| 搜索完成，但无来源 | 原有 no_sources 检查拒绝，退出码 4 |
| 搜索完成、正文与引用有效 | 通过，退出码 0 |

该组只证明校验与交付路径；不代表真实模型的检索质量。

## 真实业务验证与限制

真实矩阵覆盖强制 Sol 主搜索、简单指定 URL、中英文科研调研、React 文档、两篇指定论文、最新版本冲突、不可访问 URL、原始 PDF、严格模式仅主模型、普通 Context7 search，以及流式 Sol 主搜索。每例使用隔离配置与健康状态，顺序调用；凭据副本留在 AppData，不写入仓库。

| 场景 | 耗时（秒） | 最终验证结果 |
|---|---:|---|
| 强制 Sol 主搜索 | 14.73 | 正常返回；真实工具完成 |
| 简单指定发布页 | 3.27 | complete，auto 跳过 |
| 中文科研题，修正超长元数据后重跑 | 68.17 | 读取 4 个 URL，auto + Sol 总结成功；证据仍 partial |
| 英文科研题重跑 | 80.81 | 读取 4 个 URL，总结成功；证据仍 partial |
| React 文档研究 | 35.83 | complete，总结成功 |
| 仅两篇论文 | 21.73 | 只读指定 URL，总结成功；partial |
| 最新版本冲突 | 45.50 | 总结成功，未确认事实保留缺口；partial |
| 不可访问的指定 URL | 3.73 | 预期失败，无无关来源替代、无总结 |
| 仅原始 PDF | 11.59 | 提取并总结题名、年份、架构与任务；partial |
| 严格模式仅主模型 | 13.30 | 按既有独立证据要求拒绝，预期结果 |
| 普通 React search | 7.16 | Context7 单轮，无研究或总结 |
| 流式 Sol 主搜索 | 8.11 | stream 直接成功，工具完成，无非流式回退 |

最终选用的案例无 OpenAI HTTP 错误、429 或 Jev 调用失败/选路超限警告。中文科研题开始总结时剩余约 70.05 秒，总结实际用时 17.75 秒；没有把 120 秒总预算调大。对照的慢读文预算与总结超时/取消边界另由受控回归验证。

读文、模型回答、评估闭合与总结成功分开验收。简单指定页和 React 文档研究能闭合，普通 search 不启动研究总结；限定来源和不可访问来源仍遵守用户限制。科研题、指定论文和 PDF 的总结可成功，但其缺口评估仍可能保留 partial。最新版本题也可能只确认部分事实，不能将未读到另一条发布信息当作该版本不存在。

旧正文重放证明：Transformer 摘录保留题名和 NIPS 2017；两篇科研论文摘录同时保留 DOI `10.1016/j.ultsonch.2021.105832`、`10.1016/j.ultsonch.2025.107684`。这证明修正了输入遗漏，不等于凭元数据就能认定全部科研事实已核验。

真实测试还用于校正输入与阶段边界：提前的读文截止时间不能令最终评估把 auto 关掉；一条 Tavily 结果的标题长达 26,044 字符，不能原样复制进候选和后续模型上下文。候选标题截到 200 字符并标记 metadata_truncated，上下文的标题与 URL 也分别限制为 200 与 500 字符；原始发现记录仍保留。选路历史另外限制为操作摘要，完整工具轨迹保留在日志中，不能挤占判断预算。最终评估、有界元数据与历史均有对应回归，受影响的科研问题另做真实重跑。

当前限制：候选生成和摘录仍是有界启发式，不能保证取得所有必要资料；同源链接规则不把任意跨域链接升级为正文候选；网络提供方可失败；概率服务跨调用仍可能波动。测试没有通过调低阈值、增大总时限或强制把 partial 改成 complete 来获得通过。需要完整研究结论的调用方应检查 completion.answer、gap_check、synthesis，而不能只看 ok。
