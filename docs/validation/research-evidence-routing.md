## 真实联网

使用用户已配置的 Jev、OpenAI、Context7、Exa、Tavily、Firecrawl；每例隔离健康状态，顺序执行，避免并发测试造成主搜索 TPM 干扰。总结使用既有 auto 与 gpt-6.1-sol。期间发现并修复了读取候选缺少元数据、Jev 后续选路 max_tokens_exceeded、以及正常判断被误标为不可用的问题；最后一轮 6 例未出现 Jev 调用错误。

| 场景 | 实际结果与完成边界 |
|---|---|
| 指定官方发布页的版本号、日期、维护版本 | 三项事实均出现在证据报告，auto 跳过 Sol；当前摘录器重放已保存正文也保留三项事实 |
| 中文开放科研题 | 读取 2 个 URL，包括 Tavily 空正文后 Firecrawl 成功；Sol 明确只有一篇原始实验完整核验，未完成要求的两篇，保留 partial |
| 英文开放科研题 | 读取 3 个 URL；Sol 对照两篇原始研究，区分直接观察与模型推断；Jev 仍保留缺口，completion.answer=partial |
| React 官方文档 | Context7 解析到 React；读取官方文档并调用 Sol，说明 cleanup 与 StrictMode 的开发/生产区别；completion.answer=complete |
| 仅限两篇论文 URL | 只读取指定的两个 URL，无额外搜索或主页替代；Sol 对照材料与外推边界，Jev 仍标 partial |
| 不可达指定 URL，禁止替代 | 仅尝试该 URL 的 Tavily 和 Firecrawl；失败可见，无其他网页替代、无 Sol 调用 |
| 仅限原始 PDF | 只读取指定 PDF，Sol 返回题名、年份、架构原句与实验任务；Jev 仍标 partial |
| 普通 search | 单轮 Context7，返回 React 文档；无研究评估或 Sol 总结 |

## 仍有的限制

相关摘录仍是有限词法与文档结构启发式；真实 Jev 可能保守地保留缺口，即使 Sol 从完整正文中给出了更完整的回答。开放中文科研题在既有三轮预算内也未总能凑齐所需的两篇原始研究。本次未降低阈值、把 partial 改成 complete，或把总结成功当作证据充分；这些样本不能支持“任意复杂问题都能完整、稳定回答”的结论。

没有新增配置项或运行依赖。大候选集的分批判断会增加 Jev 调用次数；调用仍受共享截止时间约束。调用方需要完整答案时应检查 completion.answer，并同时检查 gap_check 和 synthesis；ok 继续保持检索成功的兼容含义。
